## 1. 권장 엔진: Unreal Engine 5 (5.4+)

### 1.1 선정 근거
| 요구사항 | UE5 적합성 |
|----------|-----------|
| 3인칭 근접 액션의 프레임 정밀 전투 (02 문서: 캔슬 창, i-frame, 히트스톱) | GAS(Gameplay Ability System) + 애님 몽타주 노티파이 스테이트로 캔슬 창을 데이터로 정의하는 검증된 파이프라인. 국내 액션 개발 인력 풀도 UE 숙련자가 가장 두꺼움 |
| 사인참사검 다중 소환 — 월드에 꽂힌 검의 지속 관리, 검진 결계 | 액터 풀링 + Niagara 기반 결계 라인. Mass/인스턴싱까지는 불필요(최대 4자루) |
| 한국 전통 미학의 고품질 비주얼 (먹·한지·발묵) | 머티리얼 기반 수묵 포스트프로세스, Lumen으로 여우불·달빛 동적 광원 표현 |
| 콘솔 확장 | 멀티플랫폼 인증 파이프라인 성숙 |
| 입력 지연 ≤100ms (03 문서 §4.3) | Enhanced Input + 저지연 프레임 파이프라인 설정으로 달성 가능 (내부 측정 게이트 설정) |

### 1.2 대안 비교 (기각 사유)
- **Unity 6 + HDRP**: 소규모라면 유효하나, 30인 규모 3인칭 액션의 애니메이션·전투 툴체인(몽타주, 피직스 컨트롤, 시퀀서급 컷신)을 자체 구축해야 하는 비용이 큼. 기각.
- **자체 엔진**: 30개월 일정과 팀 규모에서 논외.
- 결론: **UE5 채택. 단 GAS는 '전투 어빌리티'에 한정 사용**하고 성장·경제는 경량 자체 시스템으로 분리(GAS 전면 도입의 학습 비용 통제).

### 1.3 핵심 플러그인/모듈 정책
| 영역 | 채택 |
|------|------|
| 어빌리티 | GAS (AbilitySystemComponent는 플레이어·보스만, 잡몹은 경량 AttributeSet 전용) |
| 입력 | Enhanced Input (컨텍스트 스택: 탐험/전투/여우형태/메뉴) |
| AI | Behavior Tree + StateTree 혼용 (잡몹 BT, 보스 StateTree) |
| 컷신 | Sequencer + 커스텀 처형 카메라 시스템 |
| 세이브 | 자체 SaveGame 직렬화 + 버전 마이그레이션 레이어 (프리프로덕션부터 버저닝 강제) |
| 데이터 | DataTable/DataAsset + 구글시트 → CSV 임포트 자동화 (04 문서 밸런스 시트 직결) |

## 2. 프로토타입 범위 — 버티컬 슬라이스(VS) 정의

### 2.1 VS 목표 선언
"**2장 중반 30분 분량**: 사당 1곳 → 필드 1구역(분기 2개) → 정예 조우 3종 → 보스 '창귀 대장' 1체"를 최종 품질의 80%로 구현. 재미 검증의 최소 단위는 **검침 도약이 열린 상태의 전투**이므로 1장이 아닌 2장을 슬라이스로 선정한다.

### 2.2 VS 포함/제외 목록
| 포함 (Must) | 제외 (Won't — 본 프로덕션) |
|-------------|---------------------------|
| 검술 스트링 6종 + 캔슬 시스템 전체 | 검술 파생기 전수 시스템 |
| 소환 4종(허공발도·검침·도약·검우) — 검진은 Should | 신기해방 2단(현신), 여우 전투 변신 |
| 도술 각 계열 대표 1종 + 조합 2종(검침×축지, 호화×검령) | 조합표 12종 전체, 몽환진 계열 |
| 적 아키타입 4종(군체/습격/중장/지원) + 보스 1 | 아키타입 5~7형, 접두어 정예 |
| 자원 순환 전체(체/기/도/신기, 처형 루프) | 권능 트리 전체(축당 3노드만), 부적 제작 |
| HUD 전체 + 인장 휠 + 사당 메뉴 골격 | 도감·기록·치장, 접근성 전체(색약·리매핑만 포함) |
| 수묵 포스트프로세스 룩 확정 | 최종 컷신 퀄리티, 한국어 외 로컬라이즈 |

### 2.3 VS 검증 질문 (게이트 기준)
1. "검을 부른다"가 10분 안에 재미로 체감되는가? (외부 테스트 NPS성 설문 + 02 문서 KPI: 검침 도약 사용률 70%)
2. 도력 순환(검으로 벌고 도술로 쓰는)이 강요가 아닌 리듬으로 느껴지는가?
3. 입력~화면 반응 100ms 이하, 60fps 고정(PC 권장사양)이 유지되는가?
4. 수묵 룩과 전투 가독성이 충돌하지 않는가? (이펙트 과다 시 먹 번짐과 살기 텔레그래프 혼동 리스크)

## 3. 시스템 아키텍처 개요

### 3.1 전투 상태머신 (플레이어)
계층형 상태머신(HSM) + 상태별 캔슬 태그. 상태 전이는 전부 데이터(캔슬 테이블) 주도 — 기획자가 코드 수정 없이 창 조정 가능해야 함.

```
[Locomotion] ── 공격입력 ──▶ [MeleeString(n)]
     │                          │  cancel: [dodge, mystic, summon] + 창(f) 정의
     │                          ▼
     ├─▶ [Dodge] ◀── 캔슬 창 내 회피입력 (i-frame 2~10f)
     │      └─ 저스트 판정 → [HollinStep] (시간감속·잔상 스폰)
     ├─▶ [Parry] ─ 성공 → [Riposte] / 실패 → [ParryRecover(24f)]
     ├─▶ [MysticCast] ─ 투사체형은 발사 후 조기 탈출 가능
     ├─▶ [SummonAction] (허공발도/검침/검우/검진 서브스테이트)
     ├─▶ [Execute] (사기 노출 대상 근접 시에만 진입 허용)
     └─▶ [HitReact] / [Exhausted] / [Dead]
```
- **캔슬 테이블 스키마(초안)**: `{state, from_frame, to_frame, allowed:[...], buffer_consume:bool}` — DataTable 1행 = 1창. 02 문서 §3의 우선순위는 allowed 배열 순서로 구현.
- 입력 버퍼(12f, 큐 1)는 상태머신 바깥의 InputBroker가 소유 — 상태는 버퍼를 소비만 한다(선입력 버그 격리).

### 3.2 도술 시전 파이프라인
```
입력(퀵슬롯/인장휠)
 → [1] CastRequest 생성 {spell_id, aim, caster_state}
 → [2] 검증 게이트: 도력 잔량 → 상태 캔슬 가능? → 소환 슬롯? → 매혹 면역 대상?
 → [3] 비용 선지불 (실패 환불 규칙: 소환 위치 보정 실패 시 50%, 02 문서 §4.4)
 → [4] 태그 조합 판정: 최근 2초 내 활성 SpellTag와 조합표 조회
        → 히트 시 spell_id를 강화판으로 치환 (예: 호화탄 + 대기중 검 = 점화 인챈트)
 → [5] 실행: GAS Ability 활성화 (몽타주 + Niagara + 판정 스폰)
 → [6] 사후 처리: 누진 비용 카운터(+25%/연속), 도술서 발견 기록, 텔레메트리 이벤트
```
- **조합표는 코드가 아닌 데이터**: `CombineTable {tagA, tagB, window_s, result_spell, discovered:bool}` — 신규 조합 추가가 밸런스 작업 수준이 되도록.
- 검침 마커는 `SwordAnchorSubsystem`이 월드 단위로 관리(최대 4 + 보스 카운터용 소유권 이전 상태). 도약은 앵커 유효성(20초 수명, 거리, 내비게이션 도달성)을 이 서브시스템에 질의.

### 3.3 적 AI·조우 구조
- 잡몹: BT + 그룹 토큰 시스템(동시 공격권 토큰 2~3개 — 포위하되 다구리 금지, 02 문서 템포 보장).
- 매혹 상태: AI 팀ID 임시 스왑 + 행동 서브트리 교체(구현 단순화: 별도 '매혹 AI'를 만들지 않고 적대 대상만 반전).
- 보스: StateTree로 페이즈(70%/35%) + 패턴 셀렉터(가중치 + 최근 사용 패턴 감쇠). '기세 되받기'·'검침 카운터'는 글로벌 인터럽트 레이어.
- 조우 스포너: 디자이너용 EncounterAsset {아키타입 조합, 접두어, 토큰 수, 등장 연출} — 레벨에 데이터로 배치.

### 3.4 데이터/텔레메트리
- 04 문서의 KPI(처형 발동률, 도술 사용 비율, 사망 위치 등)를 프리프로덕션부터 이벤트 로깅. 로컬 세션 리포트 → 내부 대시보드.
- 세이브 데이터: 성장(각인/봉인구/그릇), 도술서 발견, 월드 플래그(영천수·기연 시드), 통계. 오토세이브는 사당·구역 경계에서만(전투 중 세이브 금지).

### 3.5 성능 예산 (PC 권장: RTX 3060급, 1080p60)
| 항목 | 예산 |
|------|------|
| 프레임 | 16.6ms (GPU 12ms / 게임스레드 6ms 병렬) |
| 전투 이펙트 (Niagara) | 프레임당 3ms 상한, 검우 4자루 동시 낙하가 최악 케이스 벤치 |
| AI | 동시 활성 12체 상한 (군체는 8+정예 조합이 상한 케이스) |
| 스트리밍 | 구역 경계 World Partition, 로딩 연출은 03 문서 §6.3(붓 그림)로 마스킹 |

## 4. 팀 요구 툴 (테크니컬 디자인 산출물)
1. **캔슬 창 시각화 툴**: 몽타주 타임라인 위에 캔슬 테이블을 오버레이 표시/편집 (프리프로덕션 M2까지).
2. **전투 리플레이·프레임 스텝**: 판정 박스·i-frame·버퍼 상태를 프레임 단위 재생 (QA 필수).
3. **밸런스 시트 파이프라인**: 구글시트 → CSV → DataTable 원클릭 임포트 + 값 범위 검증(04 문서 공식의 상수 자동 반영).
4. **조우 튜닝 모드**: 인게임 콘솔에서 EncounterAsset 핫스왑 + 즉시 리트라이.

## 6. 데이터 컨벤션·협업 규칙 (발췌)

### 6.1 네이밍/에셋 규칙
| 대상 | 규칙 | 예 |
|------|------|-----|
| 도술 ID | `SP_{계열}_{이름}` (계열: KR/HW/HY/SH = 검령/호화/환영/신행) | `SP_KR_VoidDraw` (허공발도) |
| 캔슬 테이블 행 | `CW_{상태}_{순번}` | `CW_MeleeString3_01` |
| 조우 에셋 | `ENC_{장}_{구역}_{순번}` | `ENC_CH2_Bamboo_03` |
| 상태 효과 | GameplayTag `Status.{이름}` 트리 고정 | `Status.Charm`, `Status.Ignite` |
| 밸런스 상수 | 시트 상의 키를 그대로 DataTable RowName으로 (수기 매핑 금지) | `Stamina.DodgeCost` |

### 6.2 협업 워크플로
- 브랜치: trunk 기반 + 기능 브랜치 짧게(3일 상한). 바이너리 에셋은 Perforce 스트림, 코드/데이터는 Git — M0에서 이중화 여부 최종 결정(팀 익숙도 조사 후).
- 전투 수치 변경은 코드 리뷰가 아니라 **시트 diff 리뷰**로 처리(§4.3 파이프라인 전제) — 밸런스 디자이너가 엔지니어 없이 하루 3회 이상 이터레이션 가능해야 한다는 것이 조직적 요구사항.
- 주간 '검증 빌드' 자동 패키징(CI): 입력 지연 측정, 60fps 벤치 씬, 세이브 마이그레이션 테스트 포함.

### 6.3 애니메이션 파이프라인 요구
- 검의 소환-소멸이 모든 공격 모션에 얽히므로, 검 메시는 캐릭터에 소켓 부착이 아니라 **독립 액터 + 어태치 이벤트 노티파이**로 관리(허공발도·검우와 동일 경로 — 손에 쥔 검도 '가장 가까운 소환'일 뿐이라는 P1 원칙의 기술적 구현).
- 몽타주 노티파이 표준 세트: `HitWindow`, `CancelWindow`, `SummonSocket`, `VFX_Ink`(수묵 잔향), `SFX_Steel` — 신규 노티파이 추가는 테크니컬 디자이너 승인 필수(노티파이 난립 방지).
